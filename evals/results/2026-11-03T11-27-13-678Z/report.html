## Fix `page_count` dropping the last partial page

`page_count` used floor division (`total // size`), so any leftover items that didn't fill a whole page weren't counted. For example, 25 items at 10 per page returned 2 pages instead of 3, and the last 5 items couldn't be reached. With fewer items than one page (such as 5 items at 10 per page), it returned 0.

This change uses ceiling division instead: `(total + size - 1) // size`.

| total | size | before | after |
|------:|-----:|-------:|------:|
| 0     | 10   | 0      | 0     |
| 5     | 10   | 0      | 1     |
| 10    | 10   | 1      | 1     |
| 25    | 10   | 2      | 3     |
| 30    | 10   | 3      | 3     |

Exact multiples and `total == 0` give the same result as before. Only totals with a partial last page change.

## Fix `page_count` undercounting when items don't fill the last page

`page_count` used floor division, so a final page with only some items on it wasn't counted. For example, 25 items at 10 per page returned 2 instead of 3, which would hide the last 5 items from anything that loops over pages.

### Change

```python
return (total + size - 1) // size
```

This is integer ceiling division. It gives the right count without converting to float and back.

| `total` | `size` | Before | After |
|--------:|-------:|-------:|------:|
| 0       | 10     | 0      | 0     |
| 10      | 10     | 1      | 1     |
| 11      | 10     | 1      | 2     |
| 25      | 10     | 2      | 3     |

### Notes for reviewers

- When `total` is an exact multiple of `size`, the result is unchanged.
- When `size == 0`, it still raises `ZeroDivisionError`, as before. This PR doesn't add input validation.
- Callers that relied on the old count, for example by adding 1 themselves to cover a partial page, would now count one page too many. Those call sites need checking.
- No tests were added in this change. The table above is a good starting point for some.
